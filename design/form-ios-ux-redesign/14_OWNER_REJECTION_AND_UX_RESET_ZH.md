## 二、用户一直在质疑的体验（用户明确陈述，与推测分开）

1. **不像在真实地改自己的车**：Change List 像填写 AI 修改申请；Style/Paint/Wheels 三个入口只是换了一种表单；照片大却缺少让人想点下去的操作乐趣。
2. **自己的车不是中心**：旧 PR #10 上传照片仅记文件名仍用 SVG 画车；新版虽加入本地真预览，仍未创造“动我的车”的感受。
3. **页面衔接违和**：Discover → 风格 → 选车/上传 → Studio → Review/Confirm → Task → Result → Garage 的多阶段决策是否必要？为什么有的返回跳 Discover，有的回 Garage？Garage 旧版本、来源选择、跨车切换太绕。
4. **选择行为缺少足够可理解的反馈**：选颜色后相片理应保持未生成，绝不能 CSS 伪换色，但用户又必须知道选了什么、为什么要付费、会得到什么；这组张力至今未解决。
5. **玩法少、改装感和持续创作动机弱**：为什么愿意第一次上传、尝试第二套 Style、再次改颜色/轮毂、收藏/对比、连续充值？四类基本玩法是否足够？如果同类 App 玩法更丰富，FORM 的 Credit 是否显得不值？
6. **商业产品目标优先**：希望做能吸引欧美车主、具备实际盈利能力的 iOS App，而不是一遍遍输出规范研究、过度加弹层或无限次自测。
7. **视觉与品牌**：曾较认可 `Midnight Garage / FORM AFTERHOURS` 的暗黑高级汽车文化气质，但明确不接受紫色线框 UI、通用模板感、网页表单感、廉价电竞感，以及汽车不够大、裁切车辆的版面；视觉不能替代 UX。
8. **竞品证据不足**：曾要求分析 Mody/Modyfy 的真正录屏/客户端交互，反对只看宣传截图或混淆名称/来源；不能根据竞品宣传断言模型效果、订阅转化或用户喜好。
9. **方案与模型能力错配**：用户反复讨论 Style + Extra + Color（包括 `Extra` 具体是什么、哪些类别应该上线、是否应该在后端配置、Prompt 先做还是菜单先定）；曾明确希望探索同时选择 Style+Extra+Color 的更有趣体验。现有 S01/S05 冻结规则禁止未批准的预生成风格覆盖和未验证的 Extra；**这是尚待决策的产品诉求与当前能力契约冲突，不等于自动允许开放新能力。**
10. **工作方式不满意**：多次修修补补后仍不好用；不希望新 Agent 反复向 Owner 索要已回答的信息，不希望没看实物就给结论，不希望用自动化检查绿灯冒充产品设计验收。能自行完成的工作尽量自行完成，减少 Codex/Agent 额度。

## 三、上一版为何『越改越差』——待验证设计诊断，不是用户事实

- 从隐藏意图切到 Change List，再切到三工具控制栏，仅改变了控件与模式表述，**未改变“先填参数再付款生成”的心智模型**。
- 使用独立的 Photo/Studio/Confirm/Task/Result 页面，把应当连续存在的“这辆车及其创作历史”切开了。
- 由于不能假生成，演示任务成功后仍显示原图并注明无 AI output。**这在诚信上正确，但不能用该 Demo 判断成品改装乐趣或付费价值**；设计试验必须明确区分 UX 可测部分和不可测部分。
- 以状态机和错误防护作为主要验收标准，缺少“是否愿意第一次点击、是否想改第二处、是否想保存”的真实用户任务和真实案例。
