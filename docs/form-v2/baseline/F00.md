## Current application inventory

- **Persistence/schema:** `server/app.ts` opens `dataDir/form.sqlite` with `PRAGMA journal_mode=WAL` and `busy_timeout=5000`. The legacy schema has `sessions(id,state JSON)`, `images(id,owner,project_id,data BLOB)`, and `reports(id,owner,task_id,reason,created_at)`. Project/version/draft/task/credits/ledger are serialized inside each owner session state; there is no V2 migration table or additive V2 schema yet. The checked-in `data/` database is runtime state and is not part of this implementation worktree.
- **Ownership/cookie:** each request resolves an `httpOnly` `form_session` cookie containing a server-generated 64-hex token. The token is looked up in `sessions`; unknown tokens create a new owner with demo credits (12 by default) or zero live credits. State and image reads filter by that owner. Cookie is `SameSite=Strict` and `Secure` only when the request is secure. Cross-origin mutation is rejected unless the configured origin is accepted by the current legacy middleware.
- **Tasks/recovery:** one active task is allowed per owner state. POST `/api/tasks` uses a caller idempotency key and a request fingerprint; it reserves one credit in a transaction before queueing. Queue/processing/uncertain status is persisted. Startup changes interrupted demo processing to queued and live processing to uncertain; live work is never auto-resubmitted. Cancellation releases once through an active-state check; success appends one version and settles the reservation; failures release once. These are process-local timers/controllers and legacy JSON-state operations, not the V2 worker/ledger contract.
- **Images/pipeline:** upload accepts a data URL for JPEG/PNG/WebP, rejects input over 10 MiB or 40 MP, rotates, limits to 2400px without enlargement, and stores normalized PNG bytes in `images`. The demo sample is read from `public/images/street-sport.jpg`. Generated/provider output is normalized through the same function before storage. Image routes return owner-authorized PNG bytes with no-store middleware. There is no separate input/master/display asset model, HEIC conversion, canonical pixel digest, quota ledger, or private V2 asset endpoint yet.
- **UI/API boundary:** the current client uses legacy `/api/state`, project, version, task, image, and report routes. `src/lib/api.ts` sends cookies and the server owns generation, credits, task recovery, and persisted drafts. The V2 API and release flag are not wired.
