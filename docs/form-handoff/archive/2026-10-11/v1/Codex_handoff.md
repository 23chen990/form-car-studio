# FORM 开发交接与验收任务

配套文件：research.md。适用基线：23chen990/form-car-studio，提交 3df0b392f4c81364a34d5083dc75284eafbe2eb1。本文是下一轮实施指令建议，不表示仓库已经修改，也不是执行付费模型测试的授权。

## 给 Codex 的开工说明

先读取仓库的 AGENTS.md（如存在）、README、package.json、shared/types.ts、shared/catalog.ts、server/app.ts、server/provider.ts、src/App.tsx、src/lib/draft.ts 和现有测试。核对当前提交与本基线的差异，不覆盖新改动。先建立独立工作分支和任务清单，再按下面依赖关系实施。

保留现有项目，不做无依据的技术栈迁移。不要把单文件拆分当作功能完成，也不要用 mock 成功替代真实生成质量。每个任务交付变更说明、测试证据、未覆盖风险及可回退方式。

## 不得破坏的行为

- 浏览、选色、撤销、比较、收藏和已有图片导出不触发生成。
- 一次确认创建一个逻辑任务，最多产生一个正式结果版本；重复提交不重复扣费。
- 历史结果不可变；失败、取消和返回不覆盖原图或旧结果。
- Demo、用户原图、真实生成与参考素材有不同来源标记。
- 技术失败不消耗用户生成次数；用户余额与供应商成本分别核算。
- 未实现的车型识别、质量检查、实时预览、4K、适配和模型训练不得用文案假装存在。
- 生产密钥不进入前端、日志、测试报告或仓库。禁止未经授权执行付费 API 调用、商店购买、生产部署和删除数据。

## T01 基线、回归和数据迁移

目标：保护已有用户数据和正确的任务行为，为契约升级提供可回退基础。

检查：当前支持的 Node 版本、构建/单测/E2E 命令、环境变量、Demo 默认值、数据库路径、恢复行为。记录真实执行的结果；环境失败单独报告，不写“全部通过”。

实施：为 sessions JSON 或后续存储模型建立显式 schemaVersion 和幂等迁移；加入代表性的旧 Project、Version、Draft、Task、Ledger 固件。迁移前后比对原图引用、父版本、收藏、余额、预留余额与流水。

验收：同一迁移重复执行不重复赠送或扣费；旧数据可查看与导出；迁移异常不覆盖原始数据库；有恢复演练。建议影响 server/app.ts、shared/types.ts、tests/server.test.ts 与新增迁移测试。

## T02 明确基础图与编辑契约

目标：支持“直接修改原图”，同时让整车探索和版本微调语义不混乱。

设计建议：使用显式 sourceRef（原图或版本）和 operation（explore/detail_edit/refine，名称可调整），与 styleId 解耦。直接改色不需要先拥有某个生成版本，也不强制套用整车风格。

编辑计划至少记录：schemaVersion、sourceRef、本次覆盖字段、继承后的期望配方、保护项、可选参考图用途、输出规格、模板版本。颜色/表面/轮毂样式应使用受控枚举或明确校验，不把任意字符串都当已支持能力。

“保留当前”表示不覆盖当前基础图的该字段；“恢复原图”是另一项显式操作。未被模型验证的属性保持 unknown 或标为请求值，不用最后一次 target 冒充实际结果。所有影响结果的语义字段进入任务指纹；任意更改必须使旧确认失效。

验收：原图可以直接单项编辑；选择旧版本不会使用最新图；改变基础图后草稿冲突被处理；没有有效修改时不会创建收费任务；复用确认不能偷偷更改输出规格或模板；旧版 explore/refine 请求保持兼容或得到明确迁移错误。

建议影响 shared/types.ts、shared/catalog.ts、src/lib/draft.ts、src/lib/api.ts、server/app.ts、tests/draft.test.ts、tests/server.test.ts。

补充验收：确认请求发出后、收到响应前发生刷新或断网，客户端仍能用同一个提交标识找回任务，不依赖只存在内存中的标识。服务端固定确认时的规格与报价；模型或价格配置后来改变，不得静默增加既有任务消耗。不同账户不得通过猜测提交标识读取他人的任务。

## T03 供应商适配与成本可观测

目标：不再只返回一段图片 Buffer，让每次真实调用可定位、可计量。

实施：返回图像、实际模型 ID、供应商请求 ID、耗时、输出尺寸与格式、usage（若有）、费用估计及其来源。用 capability 配置管理参考图、mask、多轮编辑、输出规格和支持参数。未知或不适用参数不盲传。

提示模板由允许修改与保护项生成。移除无必要的用户项目名指令拼接。对 4xx 输入错误、内容拒绝、限流、5xx、超时、解码失败、存储失败分类；对用户保留清楚的简短解释，对运营保留脱敏诊断。

不要因超时就自动切供应商：先判断原任务状态及重复付费风险。若业务允许内部补救，设置最大尝试数、总费用和时长上限，保证只结算一个用户逻辑任务。

验收：无密钥泄露；取消信号传递；请求 ID 和 usage 缺失被标为未知而不是零；模型变更与模板版本可追溯；提供者异常不重复结算；限流错误不会触发无界重试。单元测试使用 mock；真实测试需单独预算授权。

## T04 照片评测、质量规则与案例授权

目标：先证明能力，再开放菜单和商店宣传。

实施：建立获得授权的照片集，按车型、角度、光照、可见左右舵和现有改装标记。风格预设加入 enabled、supportedOperations、验证记录和素材授权引用。前台只展示达到内部要求的方向。

质量分三层：技术交付、指令与非目标保护、主观愿意保留。不要只检查图片能否解码；也不要将一个 AI 评分当绝对真值。保留首次输出和所有失败，盲评者看不到模型名与预期胜者。

验收：能导出每个方案的原图、首次结果、模型/模板、时长、费用与评审记录；Demo 不混入 live 质量指标；所有外部营销案例有授权与对应真实执行证据。配套 summarize_eval.py 仅汇总录入的真实结果，不调用模型。

## T05 首页、选图、确认与等待

目标：缩短首次路径，不以不透明上传或强制选择换取转化。

实施：首页案例可直接试用，详情可选；添加次级单项编辑入口。先在本地预览、转换或提示图片格式，再根据实际告知上传。第三方处理许可记录政策版本、处理方、用途、时间和用户身份关联，不只保存 consent=true。

确认显示基础图、修改字段、保护项、正式输出数量与次数。等待显示真实任务状态；拒绝通知不影响流程。先用任务接口获取状态，完成后刷新作品，避免持续拉取整个历史。

验收：取消选图不上传；删除与取消选用是不同动作；错误可恢复；未确认不生图；断网重连找回同一任务；重启不制造重复任务；当前页面离开不丢任务或已保存草稿。

## T06 结果页、车库和基础分享

目标：让用户看懂变化，并方便保留自己的方案。

实施：结果直接对比原图；收藏明确为 Add to favorites；自动保存状态和保存到相册分开。支持自选封面、收藏成品入口、两个历史版本比较、分支来源显示。选择参考只改草稿，不偷偷替换主图。

基础导出支持成品、前后对比与竖屏方案卡，保持全车。导出不调用生成。分享链接或配方不默认包含原图和个人信息；系统分享弹窗打开只能记为 share_sheet_opened，不能记为成功发布。

验收：比较和导出零模型调用；所有旧版本保持不变；收藏/取消收藏反馈一致；窄屏、横屏、大字体和屏幕阅读路径可用；取消系统分享不记为成功分享。

## T07 图片母版、展示图与真实输出规格

目标：防止生成质量被资产处理悄悄损坏。

实施：拆分 normalizeInput、validateProviderOutput、buildDisplayAssets 和 export。输出原始资产或受控无损母版保留尺寸；展示缩略图独立生成。分别限定输入和输出的大小、像素与格式。失败描述指向正确阶段。

验收：4096 像素测试输出不会被无条件变为 2400；超大输出按已声明规格处理而不是错误提示“重新上传小图”；不同格式可以正确下载；低分辨率放大不标为原生 4K；母版下载权限仍归所属用户。

建议影响 server/app.ts、server/provider.ts、src/lib/export.ts 及图像管线测试。

## T08 稳定身份、内购与两本账

目标：让用户换机恢复，让购买和供应商费用可对账。

实施：选择可靠的身份方案并定义游客升级合并。用户额度分 purchased/promotional/reserved 等来源；订阅权益与次数分开。购买验证与交易事件幂等，不信任客户端报出的金额或余额。退款调整保留可审计记录。

供应商费用台账与用户额度账分开，记录所有尝试，包括取消、超时和补救。未知费用等待对账，不默认为免费。另购次数不能因取消订阅或人为 TTL 被清除。

验收：重复交易通知不重复加额度；并发任务不会超扣；购买后断网可恢复；游客升级不复制免费权益；账户合并不丢已购余额；退款与迟到通知正确；独立购买余额不受订阅取消影响；支持人员只能通过有审计的操作补偿。

## T09 iOS、权限、隐私与删除

目标：完成真正可用的原生边界，不以浏览器测试替代。

实施：评估复用 React 的封装方式，完成原生照片选择、相机、分享与保存、内购、后台返回、深链接、安全区和可访问性。设计认证与 API 来源策略，不以通配 CORS 替代安全方案。

提供图片/车辆删除与账号删除。定义任务中数据、作品、备份和必要账务记录的不同生命周期。供应商变化需要检查已有同意覆盖范围。照片元数据、车牌和人脸的处理与告知一致，不把无法确认的脱敏宣称为完成。

验收：真机 HEIC/iCloud/拒绝权限/弱网/后台返回/购买恢复/删除通过；旧图片 URL 删除后不可用；备份清理策略有记录；拒绝追踪不阻止已购买功能；无未经授权的设备指纹；评测和支持数据按权限隔离。

## T10 指标、运营支持与发布

目标：上线后知道问题在哪里，并及时止损。

事件建议：style_viewed、photo_selected、upload_started、upload_completed、generation_confirmed、provider_started、task_failed、result_delivered、quality_reviewed、favorite_changed、export_completed、share_sheet_opened、purchase_verified、credit_adjusted、account_deleted。

字段最小化：任务/版本/风格/模型/模板标识、来源和实验分组、时间与错误码；不要把原图、私人提示词或个人信息直接发给通用分析服务。事件含去重键。自动保存不等于主动收藏，重试不等于留存。

运营后台至少支持任务追溯、费用核对、有限补偿、删除状态检查、能力开关、服务故障熔断和预算上限。供应商故障时暂停新扣费，允许用户查看和导出已有作品。

验收：发现质量或成本异常能够归因到模型/模板/风格；停用不影响已有历史；发布回退经过演练；商店截图、付费权益、网站与服务端配置一致。

## 合并与交付格式

每个任务给出：改了什么；为什么；影响哪些文件；实际运行的命令与结果；新增测试；截图或真实评测证据（适用时）；仍未验证什么；回退步骤。没有执行的测试写未执行，并给原因。不要提交密钥、用户原图、无授权素材和包含私人信息的日志。

首轮推荐先完成 T01、T02、T03 的契约与回归基础，并开展 T04 的小规模预算核算；不要同时扩张全部风格、视频、社区和商城。后续开发顺序按 research.md 的关卡推进。
