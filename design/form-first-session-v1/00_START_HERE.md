## 给负责人的阅读入口

先打开 `FORM_FIRST_SESSION.html`（可由下方命令生成）。电脑左侧是验收控制区，右侧是手机；手机上控制区位于界面下方。全部汽车是本交付原创的矢量示意，不是竞品图片、FORM 真正生图结果或真实模型速度的证明。

推荐按顺序体验：New user / paid → Trial hypothesis → Existing credits → Long wait → Interrupted → Failed request → Payment pending。也可选一张自己的照片：只能本地预览，原型不会上传、更不会把它偷换成示例“生成成功”。

**这次设计解决的核心问题：** 第一眼看懂变化；用自己的车开始；知道什么时候上传、什么时候收费；等待时有控制感；作品能留下；只在有新的创作需要时考虑付费。

## 六项已确定的设计决定

1. 首屏一张可对比案例，直接进入照片选择，不再必须经过长详情页。最多三个精选方向在首层；历史八个 styleId 不删除，生产开放数量仍由能力配置决定。
2. 默认商业路径：免费浏览例图，真实生成需要已批准的次数包。收费事实在选图前说明。受控一次试用是独立实验，默认关闭，不承诺首张免费。
3. 先本地看照片，再在需要生成/购买时登录。照片处理同意、登录和最终消费确认是不同含义，不能用一个含糊的“继续”全部代替。
4. 主按钮始终有解释；登录或支付返回后保留照片、风格、基础版本和草稿。支付成功不自动开始生成。
5. 等待依据服务端状态，不伪造百分比，不用强制广告、评价或通知权限留人。超过三分钟仍可以是同一有效任务，不强求三分钟内出图或付费。
6. 结果优先比较和保存；“自动存入车库”“收藏”“保存到照片”三件事用不同文字。继续微调与报告错误分开，不通过锁住已有作品逼购买。

## 本地验收命令

从仓库根目录执行：

```sh
python3 design/form-first-session-v1/tools/build_standalone.py /tmp/FORM_FIRST_SESSION.html
node --test design/form-first-session-v1/tests/*.test.mjs
FORM_STUDY_HTML=/tmp/FORM_FIRST_SESSION.html python3 design/form-first-session-v1/tests/browser_test.py
```

浏览器测试依赖已有 Python Playwright 和 Chromium；不自动下载安装。用 `FORM_CHROMIUM` 指定本机浏览器。浏览器测试报告写到本目录 `evidence/`，不要误把含私人资料的真实截图提交。
