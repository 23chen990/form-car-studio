# 竞品研究标准流程（每个 App ID × 每个商店 × 每个版本）

## 0. 创建研究卡，不直接安装/调用

最小研究键：精确 App ID + developer + storefront + version + snapshot UTC 日期 + evidenceId。Mody 与 Modyfy、两个 Car AI 永远分开。研究人员先核对 App Store 页面，再核对 EULA、测试权限、上传素材权利和预算，只有明确满足相应闸门才能从公开观察进入更深入实验。

每条观察与推断分开：OBSERVED（当次操作所见）、DEVELOPER_CLAIM（开发者声明）、USER_REVIEW_SIGNAL（个案）、INFERENCE（解释/猜测）、UNKNOWN（无法判断）。来源必须带采集日期、地区、版本或版本未知、原始链接或私有证据 ID、局限和复核状态。不得用“高信心”掩盖没有原始证据。

## 1. 月度公开基线（默认零外部费用）

针对固定 8 个 App ID：
- 逐个记录版本更新、声明功能、用户评价变化（保留评论历史日期）、IAP 可见商品及地区、隐私标签、自有公开网站。
- 价格快照保留 product 名称与可见价格，不推定付费墙、默认续费、权益次数、单图成本或收入。
- 只有能匹配同 App ID、相同商店地区及同类数据、具备以前快照时，才写“与上期相比”；否则写“新快照、没有可信环比”。
- 关键竞品 Mody、Driftshot、Car Editor、RideMint 与轻量改色 Wrapr 优先；发现新竞品需先登记 ID，不乱入历史同名记录。

## 2. 用户可见体验研究（仅在许可/预算就绪）

使用以下四条流程，以同一批授权输入、相同角度/可见细节尽量配对比较：
1. 首次打开到理解价值：记录 30 秒观察点、首页主要 CTA、是否先给示例、需要多少步才能提交第一张；没有真正生成不能记作成功。
2. 只改颜色：例如车身颜色改变，记车标、车灯、背景、玻璃、车轮是否意外变化。
3. 整车搭配：选择一套可理解的风格，记实际可见改动、审美保留意愿、品牌/车型身份。
4. 局部细化：在已生成的历史图上仅修改轮毂配色/造型，比较相同车与非目标部位；连续编辑另记相对于原图的漂移。

记录：开始时刻、有效操作数、实际生成次数、失败和重试、等待时长、可见扣次/费用、是否能保存/比较/再编辑、是否依赖付费、真实前后对比和参与者是否愿意保留结果。

严禁：为展示“好结果”隐藏第一次或失败结果；把免费 demo 当作真实模型输出；把用户评价个案当成总体故障率；使用未获授权的车主照片；不经批准购买套餐。

## 3. REA 辅助分析（仅在有明确问题时）

优先分析公开网站信息架构、按钮状态、无障碍标签和已获许可的公开网页脚本。REA Web 观察提供的是当前网页证据，不等于 iOS 原生 App 后台行为。截图与网络信息可能含令牌/用户数据，原件只允许私有存储。

若确认有合法许可与被授权的应用包，才进行针对性的静态观察，例如：App 内是否存在公开可见的模板资源、被公开声明的模型参数标识、图片处理与缓存线索。无法观察后端提示词直接标 UNKNOWN；不尝试规避加密、安全检查或专有访问控制。

研究 Agent 不得下载未授权 IPA，不得安装 root 证书或修改证书校验以读取对方 TLS 内容，不得爬取登录后私密管理接口，不得编写第三方调用仿冒客户端，更不得将获得的非公开代码/提示词复制进 FORM。

## 4. 公平对比与判定

FORM 使用既定的 30 张授权照片登记：18 开发、12 锁定留出；历史 216 次开发对照与另 36 次留出仅是研究计划，未经预算批准不能跑。竞品实际对照和通用 AI baseline 必须使用相同问题；样本未被允许发送第三方时不对该竞品运行，标 N/A，不暗中换成更好看的图。

指标分开报告：
- 首次可用图片率，不只 API 返回率；每位保留一次结果需要的次数和等待。
- 身份保持、目标执行、非目标部位、图像瑕疵、主观保留意愿。
- 实际可见支付、对用户的可见重试政策；不能推出供应商成本。
- 照片车型/角度/遮挡分组；小样本报告分子分母、不宣称全国故障率。

每个判断记录正例、反例、没做过的事情。若未获付款授权，直接跳过付费墙后的研究而非推测。 

## 5. 从证据到任务

事实记录不自动变更 FORM scope。输出与 TO_FORM.md 中的证据门槛对应的假设卡，由产品/QA 审查。已冻结 F00-F38 主线继续；新的高价值想法进入下一轮变更，不得修改正在开发的 PR #3。重大 P0/P1 的真实回归疑虑可以报告现有 PR 供审查，但同样由开发者在受审范围内修复。
