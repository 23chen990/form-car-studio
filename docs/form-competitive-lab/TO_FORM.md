# 把竞品证据转化为 FORM 决策的唯一通道

研究结果不是复制清单，也不是自动给 Codex 下单。

## 1. 四层信息，不能混写

L0：营销或单个公开评论。只能建立假设，不可直接作为“竞品已实测”的证据。

L1：真实公开界面或经允许的单次可见操作。可证实该次行为，不保证所有用户、地区/版本一致。

L2：相同授权照片、相同任务、相近条件的多次实测，有完整失败和首次输出、费用/用量观察。可在限定样本内做对照，不可推断全市场。

L3：重复/跨车型/独立复核，并已证实 FORM 当前分支在同样任务下的行为。可以成为变更建议的依据，仍需产品、成本、风险和范围审批。

技术分析的 REA 证据需标明：是包内字符串、静态推论，还是实际有权限的运行观察。代码字符串与最终生效请求不是同一个事实。UI 行为不等于隐藏供应商 Prompt。

## 2. 必须追问“FORM 当前还缺什么”

以下原 V2.2 对应点可用于定位当前任务，不表示需要打断 Codex：

| 竞品事实或实验线索 | FORM 的研究问题 | 既有规范/质量关 |
|---|---|---|
| 更容易从案例直接用在自己的车 | 首屏 30 秒内能否理解并开始？ | F13、F29、S05/S06 |
| 单项轮毂变化更准确 | 对目标执行和非目标保持分别评分 | F14、F29、F35、G06 |
| 真正能在等待时离开 | 切换 App 后能否找回同一任务、次数正确？ | F09、F10、F15、F33 |
| 对免费体验解释清楚 | 是否有可核实权益、已批准预算和真实成本？ | F27、F36、G12 |
| 保存/对比/方案复用 | 是否能在同一项目下正确存储历史？ | F16、F17、F33 |
| 隐私/照片删除与同账号隔离 | 是否有一对一可靠删除和审核记录？ | F07、F26、G09 |
| 参考轮毂/任意上传参考图 | 模型能力、权利、成本和目标控制是否已证实？ | 首发范围外，必须新决策 |
| 自动视频/社区/模型训练 | 实际带来重复使用吗、值得成本吗？ | 首发范围外，默认拒绝 |

## 3. 标准“研究建议卡”必须有的字段

- findingId 与相关 recordId；明确 APP ID、商店、版本、时点。
- 事实、反例、尚未知晓和可复核证据；营销与推断不能叫实测。
- 用户问题：普通车主完成哪个任务时遇到怎样的摩擦？
- 候选解决方案（不照抄第三方专有实现）。
- 与当前 FORM 实现提交的差距（引用具体源码或端到端测试）。
- 验证方法：至少有可观察的用户步骤和失败结果，必要时有分子分母、首次输出、成本。
- 估算工作量、隐私/支付/权限影响、产品优先级及不做的理由。
- 状态：RESEARCH_ONLY / VALIDATE_NEXT / APPROVED_FOR_BACKLOG / REJECTED。默认 RESEARCH_ONLY。

## 4. 决策审批和变更单

仅产品负责人或被授权的独立评审能将建议改为 APPROVED_FOR_BACKLOG。批准仍不是直接改 Codex 正在执行的 F00—F38。需要给开发时，新建有范围/依赖/验收/成本的变更 PR 或下个版本任务，经明确审核后交给开发。

P0/P1 已经实际证实的 FORM 缺陷，优先报告现有实现 PR #3 以免继续错下去；研究猜测不能虚报 P0。先处理 F02 已发现的数据结构问题，不用 REA 研究打断。

## 5. 月报怎样消费 REA

月报可引用已公开、已脱敏并经审查的 recordId 和汇总。没有 REA 研究记录，就写“本期 REA 未执行/无新证据”，不能根据计划和安装状态虚构新发现。

研究输出每月独立生成：
- 公开新变化/可信环比（与上月相同商店同ID比较）；
- 本月真实操作和 REA 技术证据（如有）；
- 对 FORM 当前实现的差距与验证方案；
- 新的竞争机会与放弃跟随的明确原因；
- 待用户批准的经费/法律事项。
