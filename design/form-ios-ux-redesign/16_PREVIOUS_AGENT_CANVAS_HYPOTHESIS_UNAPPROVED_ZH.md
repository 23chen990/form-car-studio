# FORM｜上一 Agent 的「汽车画布」猜想归档（**未批准，不是实施规格**）

> 2026-10-16 反思记录。用户已明确否定此前 Change List 和之后的 Style/Paint/Wheels 原型。以下仅是上一 Agent 随后提出的设计探索，不代表 Owner 满意或已批准；新 Agent 应独立反证、替代。

## 已否定的两轮方案

1. PR #10 的 `Your Changes → Add a Change → List → Create`：用户认为像填写 AI 申请表，没有改车的直观乐趣。
2. 随后的 `Explore → Photo → Studio (Style / Paint / Wheels) → Review → Task → Result → Garage`：局部照片预览和状态机虽有改进，但用户认为 UX 仍“很差劲”“越改越差”。三个工具按钮并不天然等于真实参与感，七个流程页面可能割裂车的连续上下文。

## 上一 Agent 最新提出的 **未批准** 假设

- **先比较两条路**：A「改装灵感流」——用户浏览可信同车改装案例，选择应用；B「汽车画布」——从自己的照片/旧版本出发，直接探索修改。
- **倾向 B 的理由（待验证）**：让自己的车成为长期对象，改色/造型/版本/对比在一处更连贯；A 可以作为初访的可信灵感，但不再主导所有二次使用。
- **减少主要场景**：可探索「首次欢迎/车库 → 车辆主画布 → 明确消费确认/任务状态」的架构，生成真正完成后不强制跳离画布到独立 Result；原图与版本能在汽车上下文内切换，对比、收藏与下一次修改紧贴刚看到的结果。
- **两种表达**：`Try a look`（整体方向，仅 Original/发布风格）与 `Change colors`（Body/Wheel 的受控颜色）比三个技术类别并排更接近车主语言。用户可先围绕车辆选择方向，再看到恰当的底部选项。
- **不让抽屉吃掉车**：一屏大车图为主，底部轻量操作层；对 320/375/390/430 需真机感受大小、可读性与触摸安全区。
- **只保留一次真正不可省略的确认**：在真实服务器 quote 成功后显示来源、1张、价格、余额、明确生成；不把「Review」「Confirm」变成无意义的重复步骤。
- **长期乐趣**：完成的真实版本回到汽车位置，可以按压查看真实 original、切换 V1/V2、比较、收藏，再主动发起另一笔有意愿的颜色修改。

## 为什么这些依然可能失败

- **没有真实生成，结果留在画布也不会变得好玩**：现有模拟原型生成后仍显示 source image 是符合诚信的，但缺少新图无法模拟真实“惊喜”或信用额度价值。
- **画布若只把控件摆在照片边上，仍然是表单**：要从车主的选择动机与反馈解决，不是换一个按钮位置。
- **灵感案例可信度未达标**：无授权、已验证 FORM 同车前后作品，任何营销 Hero 都不能谎称真实产出。
- **Style 与 Detail 不可自由叠加**：当前服务端 S01/S05 与用户曾希望的 `Style+Extra+Color` 存在未解决的产品/能力冲突，独立评估应解释切换成本与组合的未来可行性。
- **版本流与浏览节奏**：从 Original 与旧 V1 发起操作、两辆车切换、任务恢复、对比哪个来源、何时扣费仍需状态契约。减少页面不能偷偷失去正确性。
