# FORM｜新用户前一分钟、第一次付费与再次创作：独立产品研究
日期：2026-10-14；状态：RESEARCH / PROPOSED。面向海外以汽车爱好者为主的付费 iOS App。
不修改 PR #3、冻结 S01/S05、生产目录/价格/Provider Profile，不代表模型质量、用户留存或转化数据已得到验证。

## 一、核心判断

**已有 Explore / Build / Quick Mods / Garage 四类能力作为 MVP 足够，但不应该在首页平铺四个等价入口。** 核心体验应是「看见自己的汽车也能这样 → 轻松搭配 → 先知道价格和效果边界 → 生成自己的车 → 对比/继续打磨」，而非「进入一个 AI 图片工具菜单」。
推荐三个导航目标：Discover（我要找灵感）、Studio（我要改自己的车）、Garage（我要比较和继续）；Studio 内 Full Build（Style+0/1 Extra+Color）与 Quick Mods（已获验证的单项），并非四套模型。
真正提升复购的不是一次性输出更多图片，而是**保留同一辆车、带着确切的历史版本继续修改，并让下一步有具体、真实可用的选择**。

## 三、真正要支持的三个用户意图

1. **有想象但没有明确方案的车主**：「我的 Golf/Civic/Mustang 能变成什么样？」入口 Discover 同车真实 Before/After → Try this look on my car → 照片上传后自动带入确切 recipe，不要求再次从零选择。
2. **已经确定要尝试一个局部变化的车主**：「我的车改哑光黑/轮毂会怎样？」从 Studio/Quick Mods 直接上传照片/选原图 → 精确选项 → 报价 → 输出，不能强制先选 Style。
3. **已经有一张满意照片但还没试够的用户**：「保留这套宽体，换个颜色看看；或者比较街头版与 OEM+。」从 Garage/Result 选择精确成功 versionId 再编辑，或显式回到 original 开新分支。**不得静默覆盖原图、误用最新版本或默认重新执行上次付费任务。**

为什么不把四入口作为首页四张大卡？入口数不是玩法数，首屏还需要承载汽车证据与主 CTA；Garage 是结果资产，Quick Mods 是 Studio 内操作；减少模式解释成本可提升意图明确性，这是待验证的产品假设。

## 四、前60秒的可执行脚本（不是视觉稿）

| 时段/用户状态 | 必须看得见/能做 | 不该发生 |
|---|---|---|
| 0–5秒，第一次打开 | 一辆真实授权的**同车** Before/After，完整车身、原图可比较；醒目「Try this look on my car」与次级「Start with my photo」 | 不出现假 AI 成功结果、其他车型冒充同车、强制登录/付费、夸张“自动准确 fitment”承诺 |
| 用户点案例 | 稳定的 style/extra/color **ID 方案**被预选，支持能力/版本在服务器校验；可以先免费查看参数 | 不以视觉主题名字代替合法生图能力；关闭/过期样例不继续出售 |
| 用户选照片 | 简短拍摄提示：整车无遮挡、足够光线、角度清晰；本地预览和取消；后端只在上传被确认/授权后接触图片 | 不强制识别 VIN/年份/车型，不上传未选图片；不承诺每张都能成功 |
| Studio 编辑 | 图片仍显示原始/所选已完成版本，选项与「生成后才更新」的事实清晰；用户可换 Style/Extra/Color，1 Extra 上限 | 不通过改 CSS 或换成示意图伪装生成；不承诺动态 3D/零件适配 |
| 付款前 | 明确「1 look / x credits」、真实引用的原图/版本、选中修改、不能变的内容、能力/价格/Consent；不足时清楚说明完整商店价与单位 | 不让用户先买大包额度才知道功能是什么；不展示未核验商店价 |
| 首次成功结果 | 同车 Before/After 作为主体；保存、比较、从当前版本继续改/从原图另试；对应按钮必须有真实路由与新报价 | 不以“生成完成”替代检验，不自动扣下一次款，不给无依据“效果已应用”声明 |

**如没有1个真实、授权、质量通过的同车案例，不应把免费浏览伪装成实测生成。** 可以标「Concept」原型，但那不足以验证用户第一次付费所需的信任，需要先解决内容许可与供应商质量关口。

## 五、生成完成后，最少但有效的三个再创作建议

- 「Try another color」：当已生成方案有后续可选颜色且 capability 允许时显示；预填当前 exact versionId 和新颜色草稿，免费选择，不自动生图。
- 「Try a different build」：以原图为源，预填另一个已发布、适用于该任务的 Style/Extra/Color 组合；是**新分支**而非误改旧作品。
- 「Compare my looks」：纯本地/服务器授权结果的浏览对比，无生图消耗。

建议控件应从**当前服务器发布目录、项目已有版本与已验证能力**推导，不应使用静态「加尾翼」「换轮毂」标签去引导目前还不能执行的功能。没有合法下一步就展示有内容的保存、比较与其他已验证方案，不强凑升级入口。
可加低成本「Surprise Me」作为**免费随机选中已发布且兼容的 recipe**，但点击它本身绝不能触发付费生成或真实费用；先让用户审阅。

## 六、关于“充值是否划算”，需要新的商业证据

- 目前 F23 的离线商品目录是 5/15 logical credits；用户若只想验证一次自己的照片，是否愿意一次购买5次额度，是需要验证的**入门购买门槛风险**。
- 可提出「低承诺首次购买包（1或少量生成）」作为**后续独立审批选项**，但新增 StoreKit SKU/价格会影响 Apple 商品目录、退款/账本/本机购买测试。不要为追求转换率在本文件里擅自批准修改 F23。
- 「第1张免费」也不是天然好方案：V2 F36 默认关闭试用并有反滥用/供应商预算要求；仅在真实平均成本、存储费用、可接受欺诈预算、质量与试用策略审批后考虑。
- 上线必须展示 StoreKit 本地化真实价格；说明积分包包含多少次标准生成以及单次扣多少积分。用户查看案例/配方案/比较历史/保存已生成图不应被误收模型费用。
- 推荐监控：`discover_example_seen`、`try_look_clicked`、`photo_selected_local`、`build_recipe_validated`、`quote_displayed`、`purchase_completed_verified`、`task_succeeded`、`result_saved`、`second_build_quoted`、`quality_issue_reported`。
- 不应单看点击或模型调用。更重要的质量与利润指标：有效同车结果率、确实执行选中改件率、首次可保留结果率、二次主动生成意愿、**每个用户愿意保留作品的实际总可变成本**（计失败/重试/补偿）。

## 七、优先级与跨窗口工作边界

**P0**：一组真实授权、同车、令人心动的 Before/After；稳定且确切的案例→预填 recipe；原始/版本来源与总价清晰；真实高质量 AI 结果。
**P0**：第一次生成后「换一种颜色/另试一种造型/比较」，保留草稿与历史状态，不重复扣费。
**P1**：多一个授权验证案例、轻量免费随机组合、按视觉意图分类案例；无需社区算法或推送。
**P2**：排行榜、热榜、无限改件、多图生成、视频、Custom 自由文字、3D、复杂“游戏养成”——首发不做。

视觉窗口定稿后审批 S05；研究代码在 PR #8，正式 Style+Extra+Color Schema 仍需独立 S01/S02 审查。Codex 专注 F18→原生 Apple/StoreKit/真机，避免重复完成本产品研究。
本文件不声称用户已测试、付费已跑通、首张真实可售卖质量已验证。**目标是更快证明用户愿意为“我的车”的改装效果付费，而非完成更多功能清单。**

## 八、两组最省成本的用户测试（尚未执行）

A. 6–8位有车、关注汽车外观的欧美用户，每人不教操作，仅展示两套真实/清楚标注的 UI 初稿；问「它是做什么的」「第一次点击什么」「选项还没生成图片你知道吗」「何时收费」「完成一张后想试什么」。看实际点击，不用问引导性的“喜欢吗”。小样本只发现可用性问题，不外推转化率。
B. 对**经过授权且效果已验证**的真实同车输出，独立评价车型身份、可见部件变化、未请求变化、真实性、愿否保留；之后展示真实价格询问是否购买，并在可用环境追踪真实购买。仅口头购买意愿不算付费转化。
