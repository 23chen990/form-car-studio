# FORM 双重验收：技术可用 ≠ 用户真想上传

本文件用于新设计提案及后续真实产品的**验收方案**，不是已有通过证明。现阶段没有进行 8–12 名目标用户真实访谈、真实模型测试或真机支付联调。

## 一、最重要的三个独立闸门

| Gate | 问题 | 如何通过 | 不能代替的证据 |
|---|---|---|---|
| G-A 视觉诱因 | 车主一眼看到，真的想把自己的车放进去吗？ | 先看 5 秒的无提示解释、30 秒主动找上传入口和开放式原因；目标车主研究 | 自动截图、跑通按钮、设计者自夸 |
| G-T 交互准确与可信 | 清楚自己改哪张图、什么、花多少、怎样恢复吗？ | 任务演练＋浏览器/手机状态测试＋报价/授权可追踪 | 静态高保真、竞品宣传、模拟钱包 |
| G-R 真实效果和发布 | 模型真的能留住原车型且输出足够好、素材合法、付款/账本正确吗？ | 获授权真实案例 + 供应商评估 + 正式 iOS/StoreKit/安全审核 + 所有发布 Gate | 生成概念图片、单元测试、某评论好评 |

**任一 Gate 未过，不应写 DESIGN_APPROVED、LIVE_VERIFIED 或 RELEASE_APPROVED。**

## 二、独立场景矩阵（正向/异常）

| ID | 场景 | 预期表现 |
|---|---|---|
| UX01 | 新用户 5 秒看到首屏 | 能直接描述“上传我自己的车，看看改装后怎样”，不是一般壁纸/卖车 |
| UX02 | 用户看不懂赛车术语 | 主 CTA 和修改部位仍容易理解 |
| UX03 | 主示例图未加载 | 不空白，不错位，有重试/本地替代图；缺主视觉时不虚假催上传 |
| UX04 | 用户不愿给照片权限 | 可继续看预置演示并且知道何时才上传 |
| UX05 | 照片只有车的一部分 | 给正确构图建议，允许重选 |
| UX06 | 选了网页截屏/非汽车 | 只有能力验证可判断；至少支持预览、更换、准备检查；不能无根据说“检测通过” |
| UX07 | 来回切换两套示例方向 | 不生图，不扣次，已选意图可恢复 |
| UX08 | 想改色不换轮毂 | 保持当前底图与未选部件；面板不把车挤没 |
| UX09 | 同时选颜色与质感 | 界面分别保存，不将按钮视觉选中等同已处理成功 |
| UX10 | 没有支持轮毂能力 | 隐藏/标明不可用，不默默忽略 |
| UX11 | 提交前服务端 quote 缺失/过期 | 阻断并重新报价，不猜价、不假扣 |
| UX12 | 真实次数余额不足 | 正常引导购买次数包、正确显示 StoreKit 商品 |
| UX13 | 付款取消或待确认 | 保留草稿，不自动提交、不能假成功 |
| UX14 | 快速连点“生成” | 复用相同提交标识；最终服务端只认一个逻辑任务 |
| UX15 | 等待途中切后台/关闭 App | 可恢复同一任务，不把等待离开当失败/退款 |
| UX16 | 等待卡住/供应商超时 | 状态真实，提示可恢复，是否可补偿遵守后端账本 |
| UX17 | 输出图与车不一致/无变化 | 可以报告并进入现有 F35 审核，不能客户端任意返还 |
| UX18 | 结果页操作比较/收藏/保存 | 均不触发新生成；收藏和保存不同 |
| UX19 | 选历史版本再改 | 仅以选中的版本为 base，创建新版本，不覆盖旧版 |
| UX20 | 没有真正授权的 Before/After | 不发布概念示例为真实模型成功 |
| UX21 | 用户问是免费试用吗 | 不出现可能暗示免费但首周收费的用词；默认无免费生成 |
| UX22 | 超小屏、系统大字、VoiceOver、减少动态效果 | 无横溢、可操作、有真实语义和键盘焦点；原生另验 |

## 三、真实用户测试（建议 8–12 人）

**招募**：对改装有轻到中度兴趣的普通海外 iPhone 车主，包含改过车与从没改过车的用户。避免全找 UI 设计者或重度跑车玩家。

**任务不先提示功能：**
1. 第 5 秒遮住界面：这是什么？它与我的车有什么关系？
2. 解开到第 30 秒：你会点哪里？如果不选照片，为什么？（原话记录）
3. 让其使用示例图体验，但必须告诉他演示不是实际生成：哪张变化最吸引？是否觉得可信？
4. 让其选自己的照片或说出拒绝原因：信任/隐私/费用/看不懂/不感兴趣/图片质量。
5. 在“真实报价、一张结果”确认页问：你认为会得到什么？你以为会花钱吗？有没有误解？
6. 若已通过真实模型与授权，再让其评价输出：车型、车牌/背景、车身尺寸、轮毂、想要的改动、愿不愿存/改/再次付费。

**对照组**：不要只测改色漂亮图；提供多种普通车型同样品质的同车案例，对照“无图/矢量/漂亮概念图/已验证真实输出”的差异，研究哪种值得实际上传；不能把非等价汽车照片伪作同车 A/B。

**记录的行为指标**：首屏价值理解、30 秒内主动上传意愿、实际尝试选择照片比例、错误/返回/弃用原因、用户是否知道收费、对示例真实性的信任、第一张结果后的自发行动。样本少时先做质性归因；不虚构显著性或转化增长。

**建议设计复审门槛（提议，尚未批准）**：目标用户多数能无提示说对价值；至少有明确、自发上传行为且原因归类无系统性信任误解；所有核心报价/素材含义误解应整改。最终阈值在实施研究计划时由负责人确认，不用“8/10”这类未经商量的门槛假装已达标。

## 四、工程执行节奏与质量边界

- 设计审查一批：入口/照片工作区/确认/结果五个真实状态同时截图，而非盲目堆更多页面。
- 实现可分 F12/F13/F14/F15/F16/F17 小批，但不要打断高风险支付/迁移任务；每次按 guard 白名单审计。
- UI 浏览器测试应覆盖小屏 320/375/390/430 等、触控 ≥44pt、旋转/安全区、长文本、Reduced Motion、无网/慢图、键盘和返回、重复点击。
- iOS 真的要另外做 WebKit/真机、相册权限、StoreKit、后台任务恢复、VoiceOver、删除与退款；不能拿 Chromium 通过冒充 iOS 成功。
- 跟真实用户拿到明确批准的材料前，本次只读研究的 QA 状态均为 NOT_RUN；不用编造新测试数。
