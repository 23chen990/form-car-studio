01 产品定义与关键决策

1.1 一句话定义

面向海外移动端用户，以自己的车辆照片为主角，通过完整风格案例与 AI 搭配，帮助用户发现、欣赏、微调并保存爱车的另一种样子。产品首先服务好奇体验、审美探索和视觉创作；真实改装预览是兼容场景，不是用户获得价值的前提。

核心价值：不懂改装、也说不清想要什么的用户，仍能用少量选择得到一张像自己的车、超出原有想象、愿意留下的作品。

“看起来贴近现实”指车辆身份、比例、光影、材质和整体搭配具有可信度，不代表配件真实存在、机械适配、道路使用合规或能够按图施工。上述线下能力不纳入本版承诺。

1.3 必须成立的产品不变量

I01 选择不生成： 浏览案例、上传照片、选择风格、切换参考、撤销、保存和比较，不创建图像生成任务。照片预处理、质量检测等非生成计算需要独立记录，不能因“不生图”而宣称完全无计算成本。

I02 主图不偷换： 修改尚未提交时，主图与基础版本相同。选中的参考图不能冒充已经应用到用户车辆上的效果。

I03 历史不覆盖： 成功生成新版本后，旧版本保持不可变。失败、取消、返回和重新打开页面，不覆盖旧图或丢失必要的选择。

I04 一次确认对应一个逻辑任务： 一个成功任务最多交付一个正式版本。逻辑任务、网络请求、模型调用和最终图片不是同一个计数单位，不能等同宣传。

I05 真实性分层： 案例图、公共参考图、用户原图、用户生成结果和演示结果必须有不同来源标识。示例车不能被替换成“你的车已生成”的说法。

I06 用户无需继续编辑： 首次结果应完整可保存。进入微调、反馈或其他风格均为主动行为，不是下载图片之前的强制步骤。

1.4 明确不做的事情

本版不建立真实配件目录、品牌 SKU 匹配、安装适配、施工报价、门店交易、性能预测、VIN 必填识别、复杂三维配置器或 AR 预览。不做首屏零件大全、默认多图生成、每次点选即时 AI 重画、无限自动重试，也不把签到和每日任务作为主要复用手段。

2.3 “惊喜”的定义与边界

有效惊喜是“原本没有想到，但看见后确实喜欢”，同时仍能辨认自己的车，且不违背明确的修改约束。变化很大但用户不喜欢，不计为正向惊喜；画面很漂亮但车型改变，属于质量失败。

风格案例只让用户确定方向，轮毂、姿态与外观细节的协调由产品提供。惊喜不能通过向用户追加更多选择获得，也不能依赖默认巨大尾翼、极端低趴或改变车体身份。

典型成功情境：用户为白色日常两厢车选择 Street Sport，得到协调的轮毂、姿态与配色，发现这种搭配比原本想象更有表现力；即使不计划线下改装，保存成壁纸也构成一次完整价值。

2.4 研究问题

首轮验证三个彼此独立的问题：案例是否帮助选出方向；第一张是否值得保留；看到结果后，有限微调是否帮助用户更接近偏好。另行观察自然再次使用的理由，不用重复点击次数替代满意，也不用未发生线下改装推断产品失败。

3.2 本版微调范围为何收敛

首批只开放轮毂基本颜色与车身基本颜色，是为了验证“选参考不生图、合并确认后生成、满意部分保留”的完整闭环。两个字段可以同时修改；这不是承诺颜色编辑技术简单，而是限制初期组合复杂度。

“轮毂颜色”与“轮毂结构”必须区分。首版不把银色、古铜色与镀铬材质混成同一能力，不提供精确色号、真实膜料、尺寸或机械适配保证。整体风格仍可呈现协调的轮毂与姿态变化，用户不需要逐项指定。

04 信息架构与端到端流程

4.1 顶层导航

首版保留两个底部入口：Discover（发现）和 My Looks（我的作品）。设置与说明置于页面次级入口，不增加一个空的 Create 导航。用户从风格详情自然进入上传与生成；生成以后从结果页进入微调、比较和导出。

作品库不是工程项目管理器。底层保留图片来源、版本与草稿，前台优先展示“喜欢的作品”和“最近的结果”，不要求创建车辆项目、输入项目名称或管理树状目录。

4.3 主路径与分支

首次成功： S01 → S02 → S03 → S04 → S05 → 保存或导出。只在 S03 的明确生成按钮提交任务。

二次微调： S05 → S06 → S07 → S04 → S05（新版本）。S06 选项可反复切换，任务数量保持不变。

再次探索： S05 → S01 → S02 → S03 → S04。保留可用的原始照片，仍需明确提交；新风格从原始照片重新开始，避免把上一套改装层层叠加。

失败恢复： S04 → S11 → 查询任务状态，或在确认终止后由用户重试。失败不生成版本、不自动重试、不清空原图与草稿。

有草稿但暂不修改： S06 → 保留草稿并离开 → S05。再次进入时恢复相同基础版本；不能把草稿静默应用到另一版本。

5.2 案例生产规则

每个风格至少有一组可比较的完整前后案例。首批建议用四种风格乘以三类常见车身，制作约十二组作为内容验证起点；这是素材计划，不是上线必须一次凑足的市场覆盖结论。缺少素材的车型不伪装成已验证支持。

同组案例保持原车身份、拍摄视角和主要背景；风格区别来自车辆本身。完整车身与可见轮毂不裁掉。封面图片需授权可用，记录素材来源、使用范围与授权状态。

案例进入首页前应经过两个检查：隐藏风格名后，目标用户能否描述主要差异；换成未参与调试的普通车照片后，生成能力是否仍有相应表现。不能用极少数精选成功图代表稳定效果。

5.3 公共颜色参考

轮毂颜色首批使用 Cool silver、Graphite、Warm bronze；车身颜色首批使用 Deep blue、Cool silver、Forest green、Graphite。保留当前外观是独立动作，不强迫将当前结果归入以上色卡之一。

公共参考必须是预先制作、可复用的素材，清楚标注 Color references / Reference only。轮毂参考尽量用同一结构与光照展示色调差异；车身参考使用同一主体与构图。它们不能声称是用户车辆在候选颜色下的实时结果。

参考图可以立即切换选中态，用户自己的主图不能因此变化。 后续若开发本地实时改色，应建立独立能力标记与审核标准，不在现有参考控件中静默改变语义。

5.4 内容与能力绑定

每种风格需要 style_id、内容版本、名称、描述、封面、前后图片、默认搭配意图、颜色策略、可用车型范围、支持的后续编辑项和发布状态。每张参考图需要 reference_id、颜色标签、素材版本、适用字段和授权信息。

风格能力与素材发布独立控制。某种颜色修改在特定图片条件下不稳定时，只禁用相应微调项并说明原因，不影响用户保存已经成功的结果。下架风格不删除历史作品；历史任务保留当时的风格与素材版本快照。

8.4 S11 Recovery 与 S12 Feedback

已确认失败时提供 Retry this request，复用原任务快照创建新的逻辑任务，并记录 retry_of_job_id。状态未知时提供 Check status，不直接启动新任务。素材失效时要求恢复或换图，不能默默替换成示例车。

反馈分为身份错误、非目标变化、目标未发生、明显画质错误与审美不喜欢。用户可选填文字；发送问题图需明确授权。反馈本身不新建生成任务，不以“反馈成功”承诺问题已经修好。

技术失败不产出正式版本，已有结果和选择保持；用户取消未提交草稿不产生成本事件。对于已经提交的任务，取消请求不能删除审计记录，也不能承诺成本为零。

9.4 防重复、重试与停止

F59 防重： 客户端按钮锁只是第一层。服务端需按 confirmation_id / idempotency_key 去重；同一用户确认的重发返回同一任务。幂等键保留时长应覆盖最长任务生命周期、重连与终态恢复窗口，具体配置在接入前冻结。

F60 重试： 服务端明确失败后，用户主动点击重试才创建新确认与新 job，关联 retry_of_job_id。已提交任务仍在运行或状态未知时，优先查状态，不提供容易误触的新生成按钮。

F61 停止： 取消请求可能与成功同时发生。以服务端持久化的终态为准；若已成功，保存结果并提示任务已完成；若已取消，不创建结果。迟到回调不能重复建立版本或推翻已经确认的终态。

F62 页面恢复： 关闭应用或切换页面不等同取消。恢复后根据 task_id 查询，不依赖客户端计时器重建“成功”。默认不强制弹出结果打断当前操作，可通过任务完成提示进入。

F63 执行快照： 提交后的任务不可跟随草稿变化。任务结束时，仅清理与其对应的已提交草稿；不能删除用户后来在其他版本创建的草稿。

F64 记录： 失败、取消和重复传输均保留正确记录。停止等待页不能扣减历史提交次数；是否发生真实执行与费用由后台记录决定，不从 UI 状态推断。

9.5 资源控制规则

不自动预生成用户车辆的颜色候选，不做滑杆触发生成，不在打开结果页时生成“相关推荐”。优先用公共参考素材、现有结果缓存、零差异禁用、唯一任务与显式重试控制资源。

重复选择已存在的相同方案时，可建议查看已有版本；如果用户明确需要另一张变化，则进入另一次确认。缓存键需要包含用户或会话隔离、源图、基础版本、风格版本与请求参数，不能把另一用户的结果直接返回。

局部修改不保证按像素面积等比例降低生成成本。后台应记录实际尝试与有效结果，不用“只改轮毂所以一定很便宜”作为产品假设。本章定义资源行为，不定义费用、额度或供应商。

10.2 请求目标不是识别结果

request_snapshot 记录用户要求，例如 wheel_color = silver；verified_attributes 才记录经可靠检查确认的结果特征；未检查的字段保持 unknown。UI 不得仅因请求包含 silver，就断言当前实际轮毂一定是银色。

建立草稿时优先采用当前结果与明确的保留意图。没有可靠属性值时，基线为 Keep current。清单可以显示“当前外观 → Cool silver”，不臆测原值。若用户没有修改某一字段，不将其自动填成固定预设，以免重新生成时意外覆盖满意部分。

10.3 版本与分支

首次风格生成：source_photo_id 指向原图，parent_version_id 为空。局部修改：parent_version_id 指向用户明确选中的基础结果。尝试新风格：继续使用同一原始照片，创建新风格分支，不默认以当前已改装图片为唯一输入。

前台可以展示简单的 V1、V2、V3；内部使用不可变 ID 与真实父关系。V3 可能是 V1 的分支，不一定是 V2 的后继，比较应按 parent_version_id 取图，不能只用版本号减一。

使用旧版本继续修改不破坏新版本。源图、基础图或祖先结果被删除后，保留作品仍可打开时应说明哪些比较或继续编辑能力不可用；不能重新生成祖先图冒充原有文件。

12 非功能、隐私与可访问性要求

12.1 手机端体验目标

以下为项目目标，需在支持设备上测试，不代表已实现性能或外部认证。按钮可点击区域按不小于 44 个逻辑单位设计；最小目标手机宽度以 360 个逻辑单位作为测试起点，具体设备清单在平台确定后冻结。

纯本地的选项响应和草稿计数更新以 100 毫秒内可感知反馈为目标。该目标不适用于图像生成或网络素材下载。图片加载采用合适缩略图，不能为了展示小卡片反复解码全尺寸图片。关键 CTA 不被键盘、底部安全区或浮层遮挡。

支持读屏名称、清晰焦点和返回顺序。选择状态同时使用勾选、边框或文字，不能仅靠颜色。对比滑块提供键盘与辅助操作方式。用户启用减少动态效果时，非必要扫描动画可关闭，功能不受影响。

12.2 状态持久化与网络

风格选择、基础版本 ID、草稿和已提交任务 ID 应跨页面恢复。离线时允许浏览缓存、查看已有作品和本地导出；提交按钮需明确网络状态。弱网期间不因用户反复点按钮创建新任务。

成功结果与本机保存需有完整性校验。若图片没有成功落盘，不能仅因为元数据写入成功就显示“作品已完整保存”。图片重新下载使用原资源，不重新调用生成服务。

12.3 素材隐私与安全

产品默认作品私密，不自动发布到社区。导入前后说明生成所需的数据处理范围，向外部服务发送图片之前获得必要授权。匿名体验不等于没有隐私义务；不得把原型的“全部本地”说明直接复制到正式联网生成服务。

访问图片资源需要所有者或会话授权；使用不可猜测的资源标识与受限访问链接。上传处理检查文件内容、类型、尺寸与异常元数据。车牌、定位、姓名与原图不得进入普通分析埋点；用户反馈附图需单独明确授权。

“不会用于训练”只有在实际数据链路、供应商配置与条款均支持时才能对外承诺。删除图片、取消收藏、清除本地缓存与撤回后续处理授权是不同动作，文案与实现保持一致。

12.4 数据保留策略待冻结项

客户端临时缓存、近期生成历史、用户显式保存作品、服务端原图、服务端结果与技术日志需要分别定义期限。期限、匿名凭证恢复、账号方案与供应商删除能力必须在联网测试前完成评审，不使用“永久保存”或“取消即彻底删除”作为占位承诺。

用户删除源图时，应说明对版本比较与后续编辑的影响。尊重删除请求优先于保持隐藏的编辑链路；不能以“是其他图的父级”为由无限保留用户要求删除的素材。必要技术审计记录与图像内容分离管理。

分动机与来源观察；不要求每日使用。 | 



非预期生成 | 
无有效用户确认而出现的新增生成任务数 | 
属于发布阻断问题，目标为测试中零发生。 | 




时间指标分别记录从打开首例到确认、确认到结果可见、结果可见到保存，以及主动修改后的结果可见时间。不要把浏览时间误判成生成慢，也不要把快速离开一张满意作品等同失败。

13.3 研究任务与样本分层

首轮可先招募约 12—15 位普通车主进行定性观察，使用自己的照片完成“选一个风格，得到一张愿意留下的图”。人数为研究计划建议，不用于推算海外总体比例。招募不只来自改装论坛，还要包含普通爱车者、好奇体验者和汽车图片创作者。

观察第一次能否理解案例差异、是否误把参考当实时效果、是否知道主图尚未更新、是否理解一次合并生成，以及返回后能否找回喜欢的第一版。调整测试应让用户真实表达不喜欢的地方，不先指定“你必须改两项”。

首次满意或失败均可退出，不强迫每位用户走完整编辑链路。对没有完成生成的人也安排访谈，避免只从存活用户得出结论。后续按来源与动机统计使用，真实线下改装属于可选研究项，不作为主路径要求。

13.4 首轮验证假设

H01：看完整案例比看零件目录更容易选择起点。H02：先生成一张后，用户更容易表达局部偏好。H03：公共参考足以支持一部分颜色选择，不必实时改车。H04：合并确认能减少无意提交，而不明显阻碍修改。H05：作品保存与导出能独立形成价值。H06：错误恢复能减少重复随机生图。

每项假设至少记录支持、反例与未完成原因。若 H03 不成立，应优先缩小参考选择或改进参考表现，再评估局部实时处理，不直接把全部细节前置，也不立即无限增加 AI 候选。

发布评审同时查看功能缺陷、图像质量、来源隔离和用户理解，不只看原型是否漂亮或按钮能否点击。

B.2 替代的早期决定

本版不再以“八类 Mods 全部齐备”定义首发，不将 Create / Explore / Garage 三个入口作为必须，不强制首次多方案，不把用户当作准备购买改装件的人，不把实时参数滑杆当作默认交互。

仍保留的方向是：视觉案例建立概念；自己的车是主角；整体搭配可以带来惊喜；结果支持继续修改、保存与展示。参考轮毂图、结构编辑、写真与更多风格属于后续验证，而非本版隐含开发义务。
