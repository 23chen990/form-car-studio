# REA 的技术边界、访问前提与合规规则

核对来源：morluto/rea README、docs/installation.md、docs/browser-observation.md、docs/apple-application-analysis.md；rea-agents 6.4.0 的公开说明，截至2026-10-11。它的 README/包版本和实际连接的 MCP 工具目录可能不同，所有能力以当前真实安装和实际分析证据为准。

## 能力与“可读到提示词”的区别

| 目标 | 可能得到 | 不能据此宣称 |
|---|---|---|
| App Store 公开页面 | 描述、版本、评论、标价、隐私自报标签 | 实际付费墙、真实单图成本、生成内部请求 |
| 公开网站与获准访问的页面 | DOM、无障碍树、脚本线索、有限网络元信息、网页截图、场景比较 | 网站服务器私有源码、准确的后端系统提示词 |
| 获明确许可的 iOS IPA / .app 包 | 文件清单、资源、框架线索、可见字符串；条件具备时进一步静态分析 | 自动解密 App Store 包、完整 Swift 源码、真实运行逻辑和隐藏后端 Prompt |
| 完全公开或明确授权的 JavaScript 应用 | 模块、依赖、部分静态路由与函数联系 | 混淆代码全部恢复、服务端私密配置 |
| 授权的运行环境中的行为记录 | 用户可见状态转换、等待、失败处理等可观察事实 | 从观察结果确定模型供应商、温度、系统指令或真实推理费用 |

REA 官方 Apple 应用投影明确主要输出包结构和基于路径的桥接“假设”，不是运行时调用证明。REA 不是 iOS 破解/解密、App Store 付费墙绕过或服务器提示词读取工具。

## 提示词相关的正确研究问题

- 问题 A：风格承诺有哪些明确修改项和保留项？记录用户可见文案和实测结果。
- 问题 B：局部修改是否真的保持车灯、车标、背景和轮毂以外区域？用合法上传的同图测试和独立评分验证。
- 问题 C：修改失败会重试吗、会不会额外收费？只以实际可观察账户余额和行为佐证，不猜服务器实现。
- 问题 D：是否有可公开核验的模板、开源实现或公开开发者技术文档？若有记录来源及许可，不复制第三方专有文本。
- 问题 E：若经过明确权利核查，授权包中出现本地可见提示词的字符串线索，仅写抽象可复用原则及其限制；不要把第三方非公开原文放进公开 FORM 仓库。

## 分层许可闸门（不可自动越过）

绿：公开商店资料、官方教程、开发者公开演示、无需绕过访问限制的人工可见行为。按相应站点条款与合理访问频率使用；保留来源链接。

黄：账户内体验、本人可用合法照片、可能收费的竞品操作、网站脚本分析、网络细节或应用安装包静态分析。必须记录目标许可/地区规则、知情同意、是否含个人信息、预算、负责人的具体批准及停止条件。研究前先核对相关 EULA，必要时咨询法律专业人士。不可认为“买了 App/有账号”就自动有完整逆向许可。

红：绕过付费/登录、绕过保护或加密、获得他人凭据、截获他人流量、未经许可读取私有 API、攻击服务器、提取受保护的第三方私有系统提示词、公开分发竞品二进制或专有代码、自动刷量或伪造收益。**禁止执行。**

Apple 标准许可原则上限制逆向工程，并有适用法律及开源授权的例外；不同 App 可能采用自定义 EULA。文档不是法律意见，进入黄区前必须逐对象核对。

## 环境隔离

不在 FORM 产品开发 Codex 的工作环境安装 REA。不运行未知 curl|bash，不把 REA 放入 package.json、package-lock.json、FORM CI 或 App。单独研究设备/系统用户/工作空间使用 pin 的 REA 版本；先审批计划，再决定是否注册研究专用 MCP。

官方只读计划示例（下载执行 npm 包也有自身供应链风险，应先核验来源）： 
    npx rea-agents@6.4.0 setup --client codex --dry-run --json

该命令只展示该包提出的配置计划，不代表已安装、已授权或已连接。RE A 软件、浏览器和分析器有各自权限；给本地工具的访问权应最小化。无设备/无许可/无运行环境就标 NOT_RUN，不能以模拟输出替代。

## 必须保留的未知

第三方系统提示词、真实使用的图片模型、请求内部参数、后端重试规则、对上游的真实单次成本、长期留存和收入，除非存在明确、可核验且有权使用的独立证据，均记 UNKNOWN。
