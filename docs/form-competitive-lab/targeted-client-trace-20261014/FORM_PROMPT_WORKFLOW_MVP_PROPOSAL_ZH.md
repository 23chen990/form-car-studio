# FORM｜AI 改装 Prompt 多流程与最快商业化方案
状态：RESEARCH / PROPOSAL ONLY。2026-10-14。
基线：实现 PR #3 758477e0d1b6a358006357b586ec7917a5dd4e26；竞品证据 PR #8 bbc784f；该方案尚未获 Owner 的能力或付费模型授权。
本文件仅作产品/Prompt 设计决策，不修改 S01/S02/S05、Provider Profile、真实生成服务、任务费用与任何生产代码。

## 一句话决策
**三个任务族、同一条执行管线、一个跨任务的继续创作机制**：
1. Colorway / Style Preset：先只使用 V2 已有颜色组合预设，不冒充宽体、JDM 改件等结构改装。
2. Targeted Edit：车漆颜色/质感、轮毂颜色/样式的精确编辑，逐个字段由当前真实 Provider 能力开放。
3. Creative Build：车身套件、宽体、尾翼、悬架姿态等较大结构修改。**研究用，正式关闭**，待独立模型评估、安全/性能/成本/报价和规格审批后再开发。
4. Refine：不是第四套 AI 引擎，而是选择精确旧版本作为新的源，再进入上述合法任务。原图另试必须显式选择 original，不允许默默回退、自动用 latest。

商业版 UI 最多呈现 Studio Looks、Paint、Wheels；Creative Build 的入口未验证前隐藏，不能靠竞品标签或演示图售卖。

## 客户端逆向告诉了我们什么

| 来源 | 已确认客户端规则 | FORM 借鉴 | 不可推断 |
|---|---|---|---|

## FORM 现有真实代码，不能忽略的约束

- shared/v2/edit-plan.ts：只有 explore / detail；explore 只能 original 源、必须选已有 styleId；detail 不带 styleId。
- server/v2/plans.ts：explore 中携带 edits 会被 EXPLORE_OVERRIDES_UNSUPPORTED 拒绝。**不能照搬 Mody 的 Style＋Extra＋Color，一次生成前任意组合。**
- server/v2/presets.ts：目前 clean/sport/dark/... 预设主要是车身和轮毂颜色映射；不是已验证结构改装。
- shared/v2/provider-prompt.ts：当前允许颜色、漆面、有限轮毂造型，明确要求保持原车与场景、不增加 body kit、spoiler 等。
- Provider Profile 字段列表决定实际可用能力；静态合同里有字段不代表服务器已经验证、已经开放。F32 未接线、质量实验未执行。
- 不可为了丰富玩法，在一次用户授权的生成中暗自调用两三次模型，也不可未经批准修改现有 schema/Prompt 语义。

## 任务选择 → Prompt 组合（建议的未来通用架构）

用户选择 → 结构化意图 → 能力/范围/冲突校验 → 唯一底图及参考图来源 → 冻结 plan/price → 对应 Prompt Composer → 经评估的 Provider Profile → 1 个生成任务 → 输出质量、成本和真实来源审计。

所有 Prompt 模板都由服务器保管和版本化；客户端仅提交允许的枚举 ID，不能直接传任意 prompt、服务端 URL、mask、供应商或 workflow ID。
统一 Prompt 不是一大段不变的负面词，而是五段：
- SOURCE：主图和可选合法原图参考各自承担什么角色；
- INTENT：用户实际选中的、已批准的具体修改；
- ALLOW：本次允许改变的部件/材质/几何区域；
- PRESERVE：同车身份、摄影视角、其余未选部位；
- REALISM/OUTPUT：符合照片的反光、光源、边缘和完整车身，1 个结果。

**按允许变化生成保护约束，不得互相矛盾：**
- 改车身颜色：应保留轮毂形状、车窗、车灯、车身轮廓；车漆反光须与光源吻合。
- 改 matte/satin/gloss：允许漆面反光特性变化，保留光源方向；不能同时要求“每一个反射高光像素完全不变”。
- 改轮毂造型：保留轮心、外径、轮胎、轴距与拍摄透视；**不能又要求保留旧的辐条图案**。
- 未来增宽体：只在获准的车身局部容许外扩；保留车型辨识线条、车门/窗/灯/轴距与场景。现有“不允许增加 body kit”规则只适用于既有受限任务，不能给获批准的 Creative Build 直接套上冲突禁令。

## 三条任务族如何首发/扩展

### 1. Colorway（当前最容易实现）
以原图为底图，选一个经过授权且质量验证的整体色彩方向，自动展开已定义的车漆+轮毂颜色组合。
在当前 V2 中使用原有 explore + preset；不要额外携带 pre-generation paint overrides。
如果想实现“风格＋附加改件＋用户自选颜色”一次生成，需要另行审核新合同和模板优先级；不是用户先付三笔生成费用。
对外展示的卡片必须与真实输出相符，当前色彩类 preset 不得叫“已完成的宽体赛道改装”。

### 2. Targeted Edit（当前商业 MVP 主力）
从 original 或精确 versionId 选择源图，目标可以是 bodyColor / bodyFinish / wheelColor / wheelDesign 中**当前已获准**的一个或少量字段。
只保留此次实际有效变化；未变字段明确保护。支持 Save / Undo / Compare / Refine，但只有确认一次计划才可触发生成。
把用户看重的“保留这辆车原有特点”作为核心价值；不得承诺现实改件适配。

### 3. Creative Build（先做受控实验，不售卖）
建议先在实验库定义：Street / Track / Off-road 等大方向，每类最多 1 个被允许的可选改件与一个车漆目标。
组合优先级：实名原图身份/禁止条件 > 已验证 Style 基础方案 > 兼容的 Extra 改件 > 用户指定的合法颜色（只覆盖颜色字段）。
出现互斥/模型不支持/参数缺失时，在提交前阻止而不是拼互相矛盾的句子。
**限制单次最主要视觉变化**，第一期不开放无限多选和自由组合。需要新 Capability/新 schema/新模板/实验授权后才允许进入正式 Fxx 实现。

### 4. Refine / Try another（跨任务来源语义）
Refine this version：准确采用用户选中的已成功生成版本作为新编辑底图；对话“继续改”不是自动把上次的请求文本重新提交。
Try another from original：准确采用该 project 的 original，开启新版本分支。
旧版 recipe 只能说明过去**请求过**哪些改变；不能把未经验证的结果说成已实现的车身状态。
两种路径都要重新核当前 capability、获得新 quote、由用户确认成本；点选版本/浏览/保存不花模型费用。

## 用户自由文字 / LLM 什么时候做？

首发暂时不做自由 Prompt 输入，不需要先用 LLM 帮用户改写请求。
等出现明确需求后，自由文本只能由受审的可选解析器转换成受支持的结构化任务；无法识别的请求明确拒绝/要求用户选择，不把原句偷偷传给生图服务。LLM 成本和二次延迟需单独核算。

## 当前窗口的商业优先级

P0：先比较受限 Prompt 是否足以卖钱，尤其稳定车漆/轮毂与原车保真。
P0：独立、小额、授权的 Creative Build 实验，判断真正“惊艳感”需要的修改能力，不能只优化语气。
P1：一个任务＝一次明确用户报价；失败、补偿、退款、供应商费用按真实账本计。
P1：在真实同车效果与授权案例存在之前，不发布“已支持宽体/尾翼”等营销案例。
P2：通过再编辑、车库、导出增加留存，避免首发加入广场、3D、视频、复杂 Custom 模式。
