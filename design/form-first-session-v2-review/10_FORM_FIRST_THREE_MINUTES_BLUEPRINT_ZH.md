# FORM 前 3 分钟重设计蓝图｜设计候选，非开发批准

目标不是“像这两个竞品”，而是让普通车主在没有讲解的情况下相信**他自己的车值得放进来试**，同时不假装无授权模型能力已完成。本文件为屏幕级产品假设，不能替代现有 V2.2 状态机与支付规范。

## 价值链（每步对应用户心理）

看到可信的改装变化 → 找到适合我的车的方向 → 上传一张自己的真实照片 → 知道自己将改哪里 → 明白要花几次/多少钱 → 等待可控、任务可恢复 → 实际同车图出现 → 主动比较或继续改。

跳过“可信实例”直接催上传，用户会问“凭什么把照片给你”；堆积风格术语，用户会问“我到底要选哪个”；先显得免费分析再突兀收费，用户会担心被套路。

## 0–180 秒理想体验分镜（目标节奏，不是已测时长）

| 时间 | 可见内容与动作 | 用户应当形成的理解 | 失败信号 | 约束 |
|---|---|---|---|---|
| 0–5 秒 | 整屏主视觉：同一辆常见车、相近角度的前后变化（可拖动对比）；极短标题与“试试我的车” | “这能让我看看我的车换了样子” | 看成汽车壁纸/图库/卖车 App | 真正同车图与授权证据未准备前不得做营销事实宣称 |
| 5–15 秒 | 两三个**经质量核验**的结果方向：例如原厂↔哑光深色、轮毂整体视觉、低趴风；变更清单简短 | “哦，能改色、轮毂这类具体地方” | 不知道变化在哪里、看不见车、全是风格名 | 不可塞十几个横向卡片 |
| 15–30 秒 | 当前方向下固定主 CTA“把这套试在我的车上”；次 CTA“先用示例看看”；说明正式生成要消耗次数 | “按这个就知道我要试什么” | CTA 很大但用户不信结果、也不知收费 | 选择方向**不触发**模型消耗 |
| 30–60 秒 | 照片选择：本地相册/拍摄；配“合适/不合适”实际教学小图：完整车身、光线足、少遮挡；支持示例 | “我怎么选一张容易做好的照片” | 误用截图或人物图、照片一半车出画 | 实际解码/大小限制；未知识别能力不能假装已验证是不是车 |
| 60–90 秒 | 自己的车完整预览为主；下方默认保留已选择方向，只给最少的“车色/质感”和已验证部件选项；可以换图 | “我能改一处，不是被迫重新填表” | 车型丢失、底图太小、选择行为看起来像已生成 | 草稿变化不生图、不扣次数 |
| 90–120 秒 | 最后确认：本次基础照片/版本、改动项、保留意图、结果张数、服务端报价、取消不会丢草稿 | “我知道会获得什么、花什么” | 看不到费用或确认底图、把付款当生图 | 缺报价不能提交；支付到账也不自动生成 |
| 120–180 秒 | 若具备真实可用额度且用户明确确认：等待真实任务状态，可以离开再回来；若未解锁：在付款/身份或可浏览示例处真实停住 | “不会因为网络慢而重复扣，没让我莫名多花钱” | 虚假倒计时、假 100%、禁止返回、错误二次扣 | 不保证此时间内真实生成完成 |

> **重要：** 上述 0–180 秒不是保证玩家/车主 3 分钟得到模型结果。手机选图、授权/购买和模型延时可能超过 3 分钟；用户的“前三分钟”验收可以评价动机和清晰度，但不能把未接入真实模型时的预置图称为成果。

## 五个关键页面规格

### S0 灵感入口（第一眼）
- 主视觉占屏幕最多空间；不做 Web Dashboard 或大段卖点。只展示最好的**一组真实同车对比**，滑块可以直接拖动。
- 标题要讲受益：“看看你的车，换套造型会怎样”。辅助说明极短；给出明确修改项“车色、轮毂（经支持验证）”，不用参数名。
- 首屏主 CTA：**“把这套试在我的车上”**；次入口：“先试示例车”。底部空导航/数字/充值按钮不抢注意力。
- 若主图缺失：本地可靠替代缩略图、重试；禁止一片黑时仍弹强上传 CTA。不可让营销 AI 概念图看起来像 FORM 的实测结果。
- 禁用将用户选择立刻显示为“图已变”的假效果；指示这是候选方向。

### S1 照片准备
- 图片导入前看到好的照片范例：三分之四侧前，车身完整、不过曝；坏例：只拍到轮胎、强遮挡、人脸抢画面、非车截图。
- 上传后**只本地预览**与真实解码校验；提交服务端前进入版本化处理同意。显式告诉用户会怎么使用图片，不照抄竞品隐私标签。
- 可以换图/撤回/返回原方向；对有风险或看起来不是车的图片，可以提示用户确认，但没有模型识别服务时不能说“已自动识别”。
- 关闭权限或未选照片时应可继续浏览公开示例，不是报错死路。

### S2 车图工作区（选图后）
- 中央画面是用户原图/选中版本且**始终尽可能完整可见**；顶部简短显示“正在修改：原始照片/版本名称”。
- 底部保留已选风格意图，提供短字标签的编辑项：例如“整车方向”“车身颜色”“漆面质感”；“轮毂”必须在当前能力通过后才开放。
- 选项以底部抽屉展开，背景车图仍能看见大部；每项可以撤销选择、回到“保持原样”。
- 明确：“已选择修改，但还未生成”。在实际结果出现前不渲染假换色、假轮毂位置、假精确选区。
- 原图/指定历史版本是唯一底图；“保持”指当前底图，不偷偷退回上次结果或最高版本。

### S3 确认／付费／等待
- 提交前展示底图小图和具体修改摘要，明确只消耗**一次**、对应一张结果，真实报价必须来自服务端。找不到 SKU/服务端 quote 时阻止购买。
- 如果缺次数：经真实 App Store 商品信息显示次数包，不使用订阅套餐或“七天免费”诱导；购买取消回原草稿。
- 只有明确确认才生成；支付成功只是恢复原意图等待再次确认，不自动生图。
- 等待显示排队/处理中/结果待确认/失败的**真实状态**，可切出去再回来同一任务；未知时长不写“30 秒必成”。

### S4 结果与下一次修改
- 先展示生成的真实大图，默认能一键前后对比；可以保存、收藏、报告异常；保存≠收藏。
- 再提供“改一个地方”并创建**新的未提交草稿**，基于用户选定的本次结果或其它历史版本；不能覆盖旧版。
- 图像未变、车型明显变了、背景乱改等可以反馈并进入既有 F35 的质量补偿路径；不在客户端自行承诺返还。
- 付费弹窗不盖住刚得到的第一张结果；只有下一次确定生成才有新费用。

## 两套视觉方向该怎样利用

**上一轮 A = 上传前的惊艳入口**（但必须更换为授权、真实能力案例）；**上一轮 B 的“直接选改装项” = 选图后的操作工作区**。这不是把 A/B 的配色拼在一起，而是承认前后两个阶段的用户心理不同。两份现有 HTML 仍未通过吸引力验收。

## 体验设计必须证明的四件事

1. **视觉**：同车同角度的真实变化是否足够诱人，并能看清改动细节？
2. **信任**：用户分得清“真实输出示例 / 概念草图 / 自己的原图 / 自己的新版本”吗？
3. **动作**：主 CTA 是否将选择和上传联系在一起，而不是“上传后再想干什么”？
4. **商业**：确认前是否清楚本次结果数量、需要付钱、价格与支付状态？会不会误以为被诱导免费分析？

缺任何一项，就不能因页面漂亮/单测通过宣布“用户愿意上传”。

## 非目标

不增加 3D、视频、赛车性能/合法改装建议、AI 社交、车型数据库、零件品牌和规格准确性、精确分区涂抹、单项真实即时渲染、免费无限生成或订阅制。
