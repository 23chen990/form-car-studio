请接手 GitHub 仓库：https://github.com/23chen990/form-car-studio

**这次的真实目标：不是继续包装旧原型，而是让普通海外车主第一次看到 FORM 时，就有强烈愿望把自己的汽车照片放进去试。** 用户已明确否决旧版在这项上的吸引力。不要因为它有很多测试、文档和交互，就认定产品 UX 已经做得好。请以挑剔的付费车主、iOS 产品设计负责人、增长与定价研究员、质量审查者的视角重新评估。

## 二、用户目前最明确的不满

> 看了旧 HTML，还是觉得明显比竞品差。没有达到“让我愿意把自己的车放进去试”。另外用户英语不好，以后的快速验收材料必须中文，正式海外 App 的生产文案仍可英文。

需要严肃解释失败原因，不要“稍微优化按钮”敷衍：
- 首页以小幅扁平化矢量车为主，缺少真实高质量、可验证的改装前后视觉冲击；原图与改装后差异不够明确。
- 标题和风格名称抽象，普通车主不一定立刻理解“能把我的车改到什么程度”。缺乏强示例、可信理由、明确可实现的修改结果。
- “上传车辆照片”是隐私和心理成本较高的动作；目前没有先充分展示价值。不能仅靠免费/折扣/订阅机制催用户上传。
- 现有多个技术安全步骤、余额和模拟界面，在产品体验层显得偏重；要核查哪些确实必要，哪些可以延后到恰当时机。
- 旧原型的用户任务与后台约束虽然相对完整，但它不等于高保真、具有商业吸引力的 App 设计；大量 green tests 不应掩盖这个核心失败。

## 三、需要深入研究的真实问题

1. 竞品（至少核查 Mody、Car Editor、Driftshot、RideMint、Wrapr 和另一款对标 iOS AI car styling App）的**现行美国 App Store 页面、官方宣传视频/真实截图、首屏价值主张、案例对比、选图前体验、付费时机**。
2. 能合法获得的实际 App 操作样本，区分真实进入 App 的操作截图、开发者宣传截图、网页营销和评论个案。**不能假装已在真机安装、登录或付费**；如需竞品内购、登录或采集，请先提出预算、授权、法律及个人照片处理事项，请用户批准，不要自行购买或绕过访问控制。
3. 与“通用 AI 图片编辑工具”竞争时，FORM 必须展示怎样的专业汽车价值，而不只是另一个生成按钮？是否需要示例可切换、部件变化放大、用户车样案例、近似构图的真实前后图、明确不改变的部分？分别分析收益和维护成本。
4. 从 0–5 秒、5–15 秒、15–30 秒、30–90 秒，玩家（用户）看到什么、能做什么、获得什么反馈、在哪一步决定上传，以及为什么离开？不要单纯堆文案和复杂交互。
5. 直接购买与有限试用两套不同经济策略的视觉路径；**真实免费试用仍默认关闭**。没有模型单图成本和反滥用方案不授权免费次数。没有真实 Apple 商品信息不编造价格，不使用假倒计时、强制注册或付费后才发现功能不可用。
6. 等待、恢复、结果、保存、微调流程可以复用旧 PR #5 的安全约束，但只在用户前期被视觉效果打动后才有意义。

## 四、需要你真正交付的成果（建议一次性完成）

A. 独立的**竞品证据矩阵**：具体页面/功能/截图来源、时间、App ID、已观察事实、推测、不可验证项；直白说清我们相比竞品为什么差，不靠抽象夸赞。

B. **首屏视觉与上传动机方案**：至少两套明显不同的高质量方向（可以一套作为最佳主推），包括海报主视觉结构、真实 Before/After 看法、信任元素、CTA 和用户理解成本。不要只是换字体、换颜色。若没有获得合法真实改装案例，明确说明素材缺口，先做标注清楚的视觉草案，不得把假效果充当产品真实证明。

C. **中文可点击手机高保真原型**（必要时提供独立英文正式版文案）。尽可能直接通过浏览器打开；参考 iPhone 小屏、安全区及触控尺寸。保留关键流程但精简首屏复杂度，具备模拟的异常、关闭和返回。不要求连接真实模型、Apple Pay/StoreKit 或付费API。

D. 具体的**实现映射、状态条件、页面文案和可复现验收**。需要给能力较弱的 Codex 实施，所以写明允许文件范围、与 F12–F37 的关系、可复用组件、不能移植的模拟代码、外部素材/权益的发布闸门。拒绝重复造大型 UI/后端架构。

E. **真正的吸引力验收方法**：没有提示的首5秒用户能否讲出价值？首30秒是否愿意点“上传自己的车”？为什么不愿意？计划通过8–12个目标车主定性测试。小样本不要虚构统计显著性、真实付费转化和模型效果。成功门槛以实际证据决定。

F. 设计与文档以独立 Draft PR 提交 GitHub，严格不覆盖正在开发的 PR #3；完整演示结果、截图、测试日志和 SHA 证据。没有实际运行的测试标 NOT_RUN。若无法上传不要宣称已上传。

## 五、商业/架构约束

- FORM 是一款手机 App，不是网页 SaaS 落地页；不能把所有说明书、技术字段和测试控件挤到手机正式界面。
- V2.2 仍规定有权限、有报价、显式确认、一次请求一次扣次、版本不覆盖、任务可恢复、付款到账不自动生成、保存和收藏不同、照片处理先许可，不能为了转化率牺牲这些保障。
- 普通车主不是生成模型专家。文案少、案例强、操作少、反馈明确；引导用户想象自己车的结果，不上来教 AI 参数。
- REA/提示词/模型选择以后独立做，不用等待它才能设计页面。不得私自逆向竞品或复制有版权的图像、品牌。
- 用户不熟英文。**所有供用户验收的网页、步骤、问题单和总结以简体中文为主**。正式面向海外用户的英文 UI 文案另外维护；不要让用户先看英文才判断产品。
- 用户成本敏感，希望少量重要决策、集中 QA、少返工。不要让用户一天验收十轮；深入自行发现缺陷，不能一边完成一边夸设计。

## 六、第一步

**不要先改代码。**先读取 GitHub 的 PR #5 与现有视觉原型，重新核查真实竞品，给出明确的“为什么现在不会想上传车图”的证据与设计反思。然后提出最佳视觉方案和能立即制作的高保真原型计划，优先修复吸引力，而不是继续给旧模拟器补更多异常状态。

这是一次“产品吸引力不过关后的重新设计”，不是一般的 UI 翻译或小修补。
