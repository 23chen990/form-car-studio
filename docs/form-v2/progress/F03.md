## Implemented

- Added `server/v2/migrate.ts` and `tools/migrate-form.mjs`.
- Migration is dry-run by default and requires an explicit input database. `--apply` requires a distinct disposable output path; the source is never overwritten.
- Creates a consistent SQLite backup with WAL checkpoint plus `VACUUM INTO`, then migrates a separate working copy in one transaction.
- Imports synthetic legacy `sessions`, `images`, and `reports` into owner-scoped V2 users/projects/assets/versions/drafts/tasks/feedback and starting credit lot/ledger records.
- Uses deterministic IDs and idempotent inserts. Starting credits are imported once with a migration provenance key; no legacy grant rows are replayed on rerun.
- Converts legacy queued/processing/uncertain tasks to `uncertain`; no upstream request is resubmitted.
- Checks integrity and foreign-key state before and after migration, preserves image byte hashes, and leaves the source unchanged on failure.
- Rejects an early temporary schema marked version 2 when current owner/project constraints are absent instead of silently treating it as current.
