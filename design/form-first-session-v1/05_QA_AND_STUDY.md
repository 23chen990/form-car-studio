# QA、验收与首次体验研究

## 1. 本交付的验证分层

A. 纯逻辑参考：`tests/*.test.mjs`。检查UI行动顺序、模拟流程不变量、意图恢复和无重复模拟消费。
B. 浏览器参考：`tests/browser_test.py`。在Chromium内存页面加载离线单文件，用真实DOM操作/文件预览/窗口尺寸检查。
C. 业务联调：未执行。由原有F12—F37的harness和真实API分别接续。
D. 实机与付费：未执行。需要iPhone、Apple配置和预算。
E. 真实用户研究：未执行。不能由AI自评代替8—12名参与者。

不要将A+B次数相加称为“完整App验收”；相同测试重跑不重复计数。浏览器mock也不能证明服务端并发或Apple签名正确。

## 3. 最小真人研究（8—12位，尚未执行）

对象：普通车主，愿意看外观方案，但不要求专业改装知识。记录招募方式与是否体验过之前原型。获得研究记录同意，不把私人照片/录像放公开仓库。

主持人不教按钮，不说“你应该喜欢这个效果”。任务：
1. 看首屏30秒，合上屏幕后用自己的话解释产品做什么、哪些需要付费。
2. 找一个想尝试的方向，准备照片，观察何处迟疑；可使用研究授权样本。
3. 模拟取消登录和购买，再找回之前的选择。
4. 模拟等待90秒，问“关掉会怎样、会扣几次”；不要暗示正确答案。
5. 给示例结果，自由选择保存、比较、微调或离开；不强迫连续生成。
6. 让用户修改“自己不喜欢的一点”，不要预先告诉他选黑轮毂。
7. 在结尾问是否还有不放心的费用或照片问题。

记录：首次动作、理解错误、需主持人帮助处、实际点击/返回、停顿原因、认为照片是否已上传、认为购买后会不会自动生图。
预先记录内部通过目标（不是市场指标）：大部分参与者无指导找到入口；无人把示例当自己的AI输出、把购买看成订阅或误以为点击颜色已经收费。任何涉及金钱/照片的严重误解须修复再测。
不要给小样本“统计显著提升”“用户付费率”结论。真实结果和真实价格缺失时，不验证真实满意度/购买率。

## 4. 后续生产指标

最小事件：
`case_viewed`、`case_compared`、`photo_selected_local`、`upload_consent_completed`、`photo_uploaded`、`auth_started/completed/cancelled`、`quote_ready`、`paywall_viewed`、`purchase_pending/credited/cancelled`、`generation_accepted`、`result_delivered`、`result_viewed`、`favorite_toggled`、`export_completed`、`share_sheet_opened`、`refine_started`、`voluntary_generation_confirmed`、`quality_reported`、`resume_task`。

单事件公共维度：app build、UX版本、能力/政策版本、实验分组（若批准）、anonymous/session reference按实际隐私策略、任务类型、是否demo。不得包含图片、车牌、文件名、邮箱、原prompt、原始交易凭据或敏感自由文本。

分母必须清楚：
- 浏览示例的人 → 选择本地照片；不要求所有人都上传。
- 形成意图的人 → 明确确认请求；与授权/付费摩擦分别看。
- 被服务端接受的真实请求 → 可交付结果 → 主动保留；demo剔除。
- 自愿新探索与修复失败的重试分开。
- 支付系统成功与服务端到账分开；多次回调去重。
- 分享面板打开不是分享成功，自动保存不是满意。

以这些指标定位问题，不为了某个单独“转化率”隐藏价格或增加强制步骤。
