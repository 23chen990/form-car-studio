## 一、我反复表达过的疑惑与不满意（请不要遗漏）

### 1. 交互本身很不自然

- A1/A2/A3/A4 多轮打磨仍像模板；布局/图片比例/视觉密度常常不对。PR #10 的 `Your Changes → Add a Change` 是 AI 修改申请表，不是玩改车。
- 后来删了 Change List，换成 `Style / Paint / Wheels` 三按钮，**还是像配置表单**，没有根本变化。我看完最新原型仍明确说“交互太差，越改越差”。
- 我并不要求保留旧设计任何一个页面；请质疑 Explore、Studio、Garage 是否应该是平级结构，甚至质疑是不是要有独立 Result 页面。

### 2. 汽车没有真正成为主角

- 车主只是想让自己的车更帅、更酷、换车色、看深色轮毂或完整风格；不关心我们的 intent、draft、plan、sourceId、change list。
- 过去上传自己的图却看到了 SVG 通用车；最新原型虽然有本地真图，但仍然缺少“我正在改我的车”的直观参与感。
- iPhone 上必须保证整辆车足够大且尽量完整，不能随意裁掉车头、尾部、轮子；大弹层/说明和底部控件不能持续挡住车。
- 我想让人愿意继续点第二次、探索别的款式和保存作品，而不是只完成一笔 AI 任务。

### 3. 首次使用步骤与返回都别扭

- 旧流程 `Discover → 风格 → 车辆选择/上传 → Workspace → Confirm → Task → Result → Garage` 是否实在太绕？哪些可以合并、跳过、留在同一画布？
- 为什么选择完 Style 到后面还要再选一遍？为什么有时 Apply、有时提交草稿、有时 Review/Confirm 两层确认？
- Discover 进去为什么返回 Garage？从 Garage 选历史 V1 编辑为什么变成最新版本？跨汽车切换时原图/草稿为何可能串台？
- 如果只是看结果、收藏、比较、换一个颜色，为什么要离开当前汽车上下文进入很多页？
- 后台生成时离开/重进、报价失败、额度不足、生成失败时怎样自然恢复，不能靠死路或多层弹窗。

### 4. 玩法丰富度、竞争力与充值价值非常不确定

- 我问过：只有四种体验够吗？用户知道怎么玩吗？看得到自己车的价值和吸引力吗？与 Mody/Modyfy 一比玩法太少，会不会连下载使用的想法都没有，更不会充值？
- `Style + Extra + Color` 到底都有什么？特别是 Extra 包含什么？是不是应该先确定菜单和真正能做的效果再做 Prompt？这些是否应该由后端配置、能动态上线/撤回？
- 我曾明确提出希望首版有 Style+Extra+Color 组合生成，而现有冻结 S01/S05 不允许未经批准的 explore preset 与 detail 覆盖，也不允许未经验证的 Extra。**别忽略这个矛盾、也别擅自扩大上线能力。** 请提出可验证的阶段性解决方案、说明模型实验与产品审批要怎么配合。
- 我想知道应使用固定/版本化 Prompt 模板，还是 LLM 动态生成；不是根据竞品推测得到“必须这样做”。
- 为什么用户愿意再试一个 Style？生成 1 张要花一个 Credit，拿到作品后下一次花钱的价值和动力是什么？

### 5. 视觉与情绪体验

- 用户面向欧美汽车爱好者，主要男性；希望高级、暗黑、克制、有汽车文化的质感——`Midnight Garage / FORM AFTERHOURS` 是认可过的方向感，不代表我批准过具体视觉稿。
- 不要紫色低保真、模板工具界面、网页仪表盘、廉价电竞、过多标签/参数/状态说明。
- 需要汽车改装的兴奋、拥有一套作品的成就感、让车主主动探索的反馈；不能为“看起来丰富”上线模型做不到的夸张车身、宽体、尾翼、降低底盘或 3D。
- 哪怕暗黑画风做得再漂亮，只要操作依旧别扭就不及格。

### 6. 真实体验、竞品和事实边界

- 真实对比 Mody、Modyfy 的用户路径，优先 PR #6 的 104.6s / 126.17s 录屏证据、静态截图和已核验客户端信息。不要拿 App Store 宣传图、错误配图或者一句营销文案当真实功能/模型结果。
- 我不想看到“测试 159/159 PASS 所以 UX 已通过”的结论；那只说明软件按照既定逻辑执行，不说明用户觉得自然、有趣、值得充值。
- 项目还没有真正经过真实同车 AI 输出的授权质量验证；模拟 Concept 和用户实际结果必须分开。车身色块变化只记草稿，不许套 CSS 颜色滤镜假装 AI 已生成。
- 产品以商业化落地为目标，不要无限研究、反复低价值换肤和过度文档化；也不要求 Codex 先做你本来就能做的工作。

## 二、你必须遵守的现有能力/安全约束

- 现阶段只考虑正式发布许可的 **Explore 整体风格、Body Color、Wheel Color、Original/Version 版本、Compare/Favorite/Save/Refine**。具体风格是否允许上线，以服务端真实注册与发布能力为准。
- 不自行开放未验证的 Body Kit、Spoiler、Widebody、Lowered Stance、Body Finish、Wheel Design、自由文本提示词、3D 等。
- 正式原型需看用户自己选择的本地照片；保持整辆车 `contain`。草稿不等于真实编辑图，演示任务不能冒充真实生成结果。
- Quote 必须由服务端授权且固定，确认前明确给出单张输出数量与 Credit；样例价格/余额只能标 DEMO。不能真支付、真生图或自作主张更改额度数据库。
- Original 与历史版本来源必须明确；Look/Detail 的合法组合遵守 S01，若产品决定更改，先提出规格和质量/能力测试，不能偷偷在前端开放。
- 不改生产 `src/`、`server/`、`shared/`、不改钱包或 DB、不合并、不部署；如有写权限，只在独立研究分支/PR 添加文件并保留旧证据。

## 三、请怎样开展本次工作

1. **先诊断，不预设答案**。实际操作两代原型，用车主视角完成首次体验、原图改色、旧版继续修改、对比收藏、返回流程。列出让普通用户迷失/无聊/觉得被骗的时刻，不只是 UI 美观问题。
2. **至少两种真正不同的交互模型**，不要只是横排按钮 vs 竖排列表。例如以车辆画布为核心、以真实案例为核心，或你认为更好的第三种。对用户的第一秒体验、第一次生成、长期留存、可验证能力与业务复杂度逐项比较。
3. **敢于推翻本交接里助手的猜想**。上一 Agent 最新曾建议“单车画布 + Try a look / Change colors + 生成后在画布内呈现结果”，**这同样不是定稿**，不能视为标准答案。请明确推荐真正好的一种，解释为什么它在心理路径上更短、更有乐趣。
4. **先验证一个核心编辑屏幕，再串完整系统**。不需要再次一口气造七张精致页面。如果可用工具支持，请制作两种真正可操作、单屏、手机尺寸的独立交互实验，允许选择本地车照；真实生成之前用明确的 Draft/Concept 状态代替伪结果。
5. **理清要做和暂不能做的乐趣**。哪些微交互不会欺骗用户（例如颜色选中、改动说明、参考案例、版本切换、拖动对比已有真实图），哪些必须有实际可用生成效果才能谈？不要以未经测试的功能吸引充值。
6. **明确菜单和模型边界**。重新评估 Style / Extra / Color 是否应该作为用户界面名词；更自然的可见操作是什么？给出发布配置结构建议、受控字段与扩展闸门，区分需求与现有 S01/S05 不可违反的部分。
7. **用户测试优先于自动化绿灯**。先用简短可重复的可用性任务评估有没有“改车的参与感”和继续创作动机。8–12 人的 Demo 理解测试、12–16 人的真实效果/保真与保留意愿研究尚未执行，不可伪称通过。

## 四、我希望你最终交付

- 清晰指出最根本的 3–5 个 UX 病因（含具体旧原型中的证据）。
- 至少两个实质不同且能具体体验的方案、比较和坚定的首选，并公开最可能失败的地方。
- 第一屏的行为设计与编辑核心屏交互方案：为什么每个动作在这里、下一步是什么、用户会有什么感受。
- 首次创作与多次回来创作的用户旅程；保留 Source、Version、Credit、Task 正确性但降低认知负担。
- Style/Extra/Color 的取舍与后台发布能力/生图验证阶段图；哪些功能现在没有依据不能上线。
- 简洁但可检验的使用者任务与验收标准，以及现阶段**不能被原型证明**的商业价值假设。
- 若制作了原型：独立可打开、实际点通的 HTML 和真实移动尺寸截图，测试边界诚实标注。若 GitHub 写权限可用，**保留旧证据并在研究分支提交，禁止改生产/合并**。

**最终原则：不要再让 FORM 只是一个更规范的 AI 编辑申请表。我想要一个车主无需学习，就会感到“这真的是我的车，我想再试一次”的产品。你可以否定以前所有 Agent 的建议，但请用真实流程和可以操作的证据让我理解你的判断。**
